    CISSP Study Notes（CISSP復習ノート）— 利用・更新ガイド

    版：1.0 / 資料確認日：2026-09-12

    この初版に含むもの

    Domain 1の普段の復習用本編、網羅性確認表、問題履歴の反映台帳、出典・最新性台帳、共通のHTML閲覧版と生成スクリプトです。Domain 2〜8の本文、試験直前版は含みません。2026-09-13にGitHub Pages公開用の同期手順を追加しました。CISSPの本編内容は変更していません。

    本編は約4.5万字で、公式12領域に判断の基礎と応用例を加えています。本編、網羅性、履歴、出典へ進めます。

    履歴上の制約：全111問の個別原文・回答は取得できていません。Q95〜98の個別回答、提供された学習要約、完走時総括を利用し、根拠区分を明記しました。公式範囲の収録と、個人の全回答の照合は別の確認です。

    閲覧する

    一式を同じフォルダ構成のまま取得・展開し、site/index.htmlをブラウザで開いてください。生成済みHTMLの閲覧に、Node.js（JavaScript実行環境）やネット接続は不要です。CSS・JavaScript・ページ間リンクは相対パスで参照します。本文には外部の画像・フォント・配信ネットワークへの依存がありません。

    PCでは左側の目次、狭い画面では「このページの目次を開く」を利用します。比較表は横へスクロールできます。検索はそのページの本文にある節を探し、本文自体は常に表示します。英語・日本語、大小文字、全角・半角を可能な範囲で正規化し、空白で複数語を指定するとすべてを含む節を探します。

    夜間表示は上部のボタンで切り替えます。設定を保存できる環境では同じブラウザに記憶し、保存できなくてもその場で切り替わります。JavaScriptを利用しない場合も本文・リンク・目次・比較表は読め、配色は端末の設定に従います。検索・手動配色切替・現在章の追跡はJavaScriptによる追加機能です。

    iPhoneでの位置付け：HTMLはiPhone相当の画面幅を想定したレスポンシブ設計です。DriveやiOSのファイルプレビューが複数ファイルのHTMLをWebページとして実行することは前提にしていません。GitHub Pagesの公開設定後は、PCとiPhone Safariから同じURLで閲覧できます。WebKit／実機での最終確認状況は品質報告と公開作業報告を参照してください。

    ファイル構成

    場所 役割 編集するか
    content/domain1/CISSP_Domain1_Master.md 学習内容のMarkdown正本 本文を更新するときに編集
    coverage/Domain1_Coverage.md 公式範囲と本文・履歴の対応 範囲・参照先を更新
    references/Problem_History.md 演習情報の根拠と反映 新しい履歴を根拠付きで追記
    references/Sources.md 出典・版・検証範囲 調査時に更新
    book.json Domain・資料ページの登録 本文追加時に編集
    ui/style.css、ui/app.js 共通デザイン・操作性のソース 全Domainの表示を変えるときに編集
    build/build.mjs MarkdownからHTMLへの生成 生成規則を変えるときのみ編集
    templates/Domain_Master_Template.md 新しいDomainの構成ひな形 コピーして利用
    vendor/marked/ Markdown変換ライブラリとライセンス 通常は変更しない
    site/ 生成したHTML・共通CSS・JavaScript 直接編集せず再生成
    quality/ 内容・表示・納品の確認報告、ファイル一覧 確認結果を更新

    本文の更新・再生成

    1. 対象のMarkdown正本を編集します。
    2. 必要に応じて網羅性・出典・履歴も更新します。
    3. Node.js 22以降の環境で、フォルダのルートから次を実行します。
    node build/build.mjs
    1. site/index.htmlを開き、変更した節・比較表・参照リンクを確認します。
    2. 配布する場合はsite/だけ、編集可能な一式を渡す場合はフォルダ全体を更新します。

    初回もnpm installは不要です。Marked（Markdown変換ライブラリ）17.0.5をライセンスとともに同梱しています。生成処理は外部通信を行いません。実行位置が変わっても、スクリプト自身の場所を基準にファイルを解決します。

    生成時に、重複する出力先、重複アンカー、未登録のMarkdown参照、存在しない参照先アンカーを検出すると停止します。エラーを修正して再実行してください。生成されるsite/build-report.jsonは確認数などを記録した機械可読の結果です。内容の正しさは自動検査だけでは保証できないため、本文の見直しも必要です。

    Domain 2〜8を追加する

    1. 公式の最新範囲を確認し、そのDomainの目次を作ります。
    2. templates/Domain_Master_Template.mdを、たとえばcontent/domain2/CISSP_Domain2_Master.mdへコピーして本文を作成します。
    3. 見出しには{#d2-01}のような固有のアンカーを付けます。別Domainとのリンクは、相対パスのMarkdownファイルとアンカーを使います。
    4. coverage/Domain2_Coverage.mdを作り、問題演習の情報をE／S／U等の根拠区分で対応させます。
    5. book.jsonのDomain 2項目へsourceとoutputを追加し、資料ページもpages配列へ登録します。
    {
  "id": 2,
  "title": "Asset Security（資産のセキュリティ）",
  "source": "content/domain2/CISSP_Domain2_Master.md",
  "output": "domain2/index.html"
}
    1. 同じ生成コマンドを実行します。Domainの入口・移動・目次・検索・配色は共通コードが自動で適用します。DomainごとのCSSやJavaScriptは作成不要です。

    編集のルール

    重要な英語用語には日本語を添えます。新しい用語が必要な節だけを厚くし、重複説明は相互参照へ整理します。例・計算の仮定・過去の回答事実・推定を区別します。{#d1-09-quant}のようなアンカーはリンクに使われるため、見出しの文字を変えても可能な限り維持してください。

    共通の強調枠は標準Markdownの引用で記述できます。

    > **Exam Perspective（試験での考え方）**：判断原則。

> **Common Trap（よくあるひっかけ）**：誤解と、成立しない理由。

> **Problem-derived Insights（問題演習由来の知見）**：確認した根拠と一般原則。

    生のHTMLは本文に埋め込まず、生成時には文字列として表示します。表・コードブロック・通常のMarkdownリンクを使ってください。参照先がMarkdownの場合、book.jsonへ登録したページは生成時にHTMLの相対リンクへ変換されます。

    分析用の外部送信はありません。本文の更新と閲覧基盤の更新を分けて維持できます。

    GitHub Pagesへ反映する

    正本は引き続きGoogle DriveのCISSP/CISSP_Study_Notes/です。GitHubの19990202ray/cissp-study-notesは公開用成果物を管理します。publishing/README_GitHub.mdに公開設定と更新手順、publishing/sync-site.mjsに再生成・同期処理を置いています。

    Node.js 22以降で、互いに別のフォルダとして取得した正本と公開リポジトリを指定します。

    node publishing/sync-site.mjs /path/to/CISSP_Study_Notes /path/to/cissp-study-notes

    処理はMarkdownからHTMLを再生成し、site/の中身をリポジトリ直下へ同期します。相対リンク・アンカー・公開側の独自変更を検査します。変更した正本と再生成したsite/をDriveへ保存してから、リポジトリのmainへコミット・pushしてください。GitHub側の本文だけを編集しないでください。

    Pages設定は「Deploy from a branch」「main」「/(root)」です。公開後の入口はトップページ、本文はDomain 1です。URLの利用にはPagesの設定・配信完了が必要です。
